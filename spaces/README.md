# Пространства

Каждое пространство — это **один файл** `spaces/<id>.js`. Он описывает сеть, данные и пояснения,
а рендер, подсветку, боковую панель и режим с числами берёт на себя общий движок (`src/engine/`).

## Как добавить пространство

1. Скопируйте [`_template.js`](_template.js) в `spaces/<id>.js`, где `<id>` — латиница в нижнем регистре,
   цифры и дефисы (например, `iris-classifier`).
2. Заполните `meta` (название, категория, описание) и опишите сеть.
3. Сделайте push в `main`. При деплое GitHub Actions пересоберёт `spaces/manifest.json`,
   проверит конфиг, и пространство **само появится в каталоге**. Страница пространства:
   `space.html?id=<id>`.

Проверить локально:

```bash
bash tools/build-manifest.sh      # обновить список пространств
node tools/check-spaces.mjs       # проверить конфиги (нужен Node 18+)
python -m http.server 8000        # открыть http://localhost:8000/
```

## Правила

- Архитектура и логика сети **зашиты в конфиге** — из интерфейса их менять нельзя
  (исключение — `playground.js`, где это и есть смысл пространства).
- Конфиг **не импортирует Three.js** и модули рендера — только модели из `src/engine/models/`.
  Благодаря этому каталог загружает все конфиги быстро, а `check-spaces.mjs` может проверить их в Node.
- Все тексты — на русском.

## Поля конфига

| Поле | Обязательно | Что это |
|---|---|---|
| `meta.id` | да | Совпадает с именем файла |
| `meta.title`, `meta.summary` | да | Название и краткое описание (карточка каталога и шапка панели) |
| `meta.category` | да | `basics`, `vision`, `nlp`, `tasks`, `training`, `library` — см. `src/engine/catalog.js` |
| `meta.order`, `meta.level`, `meta.uses`, `meta.tags` | нет | Порядок в категории, сложность 1–3, «где применяется», теги |
| `meta.preview` | нет | Нейронов в слоях для мини-схемы в карточке, например `[3, 4, 2]` |
| `type` | нет | Визуализатор; сейчас `mlp` (полносвязная сеть) |
| `model` | да* | `{ layers, activation, outputActivation, seed }` — движок создаст `MLP` |
| `createModel()` | да* | Своя модель вместо `model`: например, MLP с готовыми весами (см. `xor.js`) |
| `names` | нет | `{ input: [...], output: [...] }` — подписи нейронов входного и выходного слоёв |
| `inputs` | нет | Готовые входы: `[{ name, values }]`; появится выпадающий список |
| `randomInput` | нет | `false` — убрать из списка «Случайный вход» |
| `randomizable` | нет | `false` — спрятать кнопку «Новые веса» |
| `editable` | нет | `true` — разрешить менять архитектуру и активацию (только для песочниц) |
| `intro` | нет | HTML в начале карточки «Сцена» |
| `sections` | нет | Дополнительные карточки-пояснения: `[{ title, html, open }]` |
| `explainResult(ctx, acts, helpers)` | нет | Свой текст в карточке «Результат» вместо стандартного |

\* нужно одно из двух.

`explainResult` получает `ctx = { model, values, names }`, активации всех слоёв `acts`
и помощники `{ outputBarsHtml, formatValue, escapeHtml, defaultResult }`.

## Новый тип визуализации

Если пространству нужна не полносвязная сеть (свёртки, внимание, поверхность ошибки),
добавьте визуализатор в `src/engine/` и зарегистрируйте его в `VISUALIZERS` в
`src/engine/boot.js`. Общая сцена (`SceneKit`: рендер, свечение, подписи, камера) и блоки
боковой панели (`sidebar.js`) переиспользуются.
